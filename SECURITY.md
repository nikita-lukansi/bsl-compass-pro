# Безопасность развертывания

Контур рассчитан на **локальный** запуск. «Localhost-only» — свойство
docker-compose (биндинг `127.0.0.1:8240`), а НЕ приложения: uvicorn слушает
`0.0.0.0`. Любой другой способ запуска (`docker run -p 8240:8240`, правка
ports, запуск модуля без compose) публикует панель и MCP в сеть.
Локальный биндинг — не гарантия: любой процесс машины и браузерные векторы
(DNS rebinding) могут достучаться до localhost-порта; задавайте ADMIN_TOKEN.

## 1. Гейты доступа

Слои защиты HTTP-интерфейса (панель + MCP + REST):

- **`ADMIN_TOKEN`** — гейт мутирующих эндпоинтов и owner-видов. По
  умолчанию пуст: всё перечисленное доступно без токена (защита — только
  localhost-биндинг compose). При доступе с других машин (туннели,
  прокинутые порты) обязательно задайте `ADMIN_TOKEN=<длинная случайная
  строка>` в `.env`. Поле авторизации — `Authorization: Bearer <токен>`
  или `X-Admin-Token`; сравнение timing-safe. Панель шлёт токен во все
  свои запросы.
- **Origin/Host-гейт мутирующих POST** — чужой `Origin` или `Host`
  (не localhost-семейство) → 403 (CSRF, DNS rebinding); POST с телом без
  `Content-Type: application/json` → 415 (режет cross-site text/plain).
  Отсутствующие Origin/Host (не-браузерные клиенты) не блокируются.
- **Глобальный Host-гейт** — входящие запросы с `Host` вне
  localhost-семейства (localhost, 127.0.0.0/8, ::1) закрываются на уровне
  приложения, независимо от способа запуска: даже если порт опубликован
  в сеть, запрос по внешнему имени хоста не пройдёт.
- Docker-инфраструктура: маунт docker.sock и docker CLI в рантайм-образе
  выпилены; смена параметров запуска — правкой compose +
  `docker compose up -d --force-recreate` вручную.

## 2. Owner-виды (за ADMIN_TOKEN)

Эндпоинты, отдающие чувствительное (журнал вызовов, задачи и сырые
ответы 1С с деанонимизацией):

- `GET /api/journal` — журнал вызовов панели/агента;
- `GET /api/offline/tasks`, `GET /api/offline/tasks/{id}` — задачи
  офлайн-конвейера (включая деанонимизированные результаты);
- `GET /api/offline/requests/{name}` — заявки `req_*` из `queue/`
  обмена (не ответы): params в них — исходные значения токенов,
  без маскировки.

## 3. Данные 1С и анонимизация

- доступ к базе — сеанс профильного пользователя 1С «только чтение»; RLS
  базы действует и является фичей;
- обезличивание — на стороне ядра, на уровне сериализации офлайн-ответа:
  ВСЕ строковые значения ответа 1С → per-chat токены
  (`Контрагент_Т3` — осмысленный префикс из списка сущность+поле,
  `Значение_ТN` — прочее); whitelist: числа/булевы, ISO-даты
  (ГГГГ-ММ-ДД, включая время/таймзону), GUID (36 симв. с дефисами),
  пустые строки; ключи колонок и служебные поля (method/ok/code) не
  маскируются. Ошибки отдаются как `{code, masked_message}` — класс
  (ACCESS_DENIED/FIELD_NOT_FOUND/SYNTAX_ERROR/OTHER) не маскируется.
  Деанонимизация — на выдаче в панель (owner-виды, см. §2) и при
  подстановке токенов агента в params нового запроса;
- границы маскировки — честно: маскировка действует только в
  офлайн-конвейере обмена; в онлайн-режиме ответы 1С уходят агенту
  как есть (без маскировки); тул `offline_deanonymize` по запросу
  агента возвращает исходные значения известных токенов своего чата;
  вложенность глубже 8 уровней не маскируется;
- словарь токенов per-chat, TTL 24 ч, лимит 10k на чат (переполнение —
  честный сброс); одинаковые значения → один токен;
- сырые (неанонимизированные) ответы оседают в `archive/` обмена, TTL по
  умолчанию 7 дней (`ARCHIVE_RAW=off` отключает);
- граница защиты — от случайной утечки (сквозная маскировка закрывает
  представления ссылок, разыменования через точку, Код/НомераГТД).
  Whitelist-типы (числа, даты, GUID) проходят как есть — сами по себе
  не идентифицируют; словарь обратим и живёт 24 ч.

## 4. Исходящие сетевые потоки

| Поток | Что уходит | Управление |
|---|---|---|
| GitHub: проверка версии | GET `api.github.com` — сравнение SHA образа с HEAD main (репозиторий, коммиты) | **включено по умолчанию**; `UPDATE_CHECK=off` в `.env` выключает |
| GitHub: карточка репозитория | GET `api.github.com` — звёзды/ссылки для шапки панели (кэш, прогрев при старте) | только чтение |
| Эмбеддинг-API (векторизация и `codesearch`) | тексты карточек методов: «Метод <имя>(<параметры>) — <тип модуля> <объект>» для каждого метода конфигурации; текст запроса агента при поиске. **Тела методов не отправляются.** | `EMBEDDING_*`; on-prem альтернатива — локальный vLLM/Ollama с OpenAI-совместимым API |
| ИТС (корпус документации) | `its.1c.ru` / `login.1c.ru`: **учётные данные ИТС** (`ITS_LOGIN`/`ITS_PASSWORD` или `ITS_COOKIE`) уходят на форму логина 1С при выгрузке корпуса; cookie-сессия живёт только в ОЗУ процесса, на диск не пишется | не настроено — выгрузки нет (поиск/чтение готового корпуса работают без сети) |
| Telegram-нотификации | display_name конфигурации и 300 символов лога | `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`; не настроено — не отправляется |

Учтите: провайдер эмбеддингов видит перечисленные тексты всех методов
конфигурации (имена, сигнатуры, принадлежность объектам). Для закрытых
контуров разворачивайте эмбеддинги локально. Qdrant — внутренний сервис
того же compose-проекта (наружу не публикуется, ходит только ядро).

## 5. Каталог офлайн-обмена

`/data/system/offline` (queue/archive) — защищаемый периметр: любой
`req_*.json` из queue/ будет исполнен формой «Обмен» обработки КомпасРантайм
(только read-only SELECT, блок-лист мутирующих ключевых слов). Пакеты не
подписываются — не подключайте каталог туда, куда пишут посторонние.

## 6. Как сообщить об уязвимости

Приватно, не через публичные issues:

- **GitHub Security Advisories**: репозиторий → Security → Report a

Пожалуйста, приложите версию (git_sha из `/health`), способ запуска и
шаги воспроизведения. Публичное раскрытие — после фикса и релиза.
