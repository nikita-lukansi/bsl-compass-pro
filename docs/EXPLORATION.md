# Изучение незнакомой конфигурации 1С — инструкция агента

Незнакомая конфигурация? Здесь маршрут агента: от карты подсистем к
доказанным выводам, без «наверное».

Стратегия работы с компасом на незнакомой конфигурации (две боевые
обратки 2026-11-15/16 — методика выведена практикой). Что вызывает каждый
тул — справочник [TOOLS.md](TOOLS.md); здесь — маршруты и правила.

## 1. Протокол доказательности

- Любое утверждение о метаданных — через оракулы `verify_field` /
  `check_claims` (батчем), не по памяти и не по синониму. Оракул даёт
  `evidence` — тип, секцию, счётчики; его можно цитировать в выводе.
- `holds: true / false / null` — не одно и то же (см. «Честные границы»
  в TOOLS.md). Критичный `false` перед дорогостоящим решением
  перепроверяется вторым способом (`object_overview`,
  `predefined_details`).
- **«Не подтверждено — так и пиши»**: недоказанный хвост помечается
  именно как недоказанный. Лучше честное «не знаю», чем правдоподобное
  «наверное».
- Перед живыми запросами к данным (`data_query`, `records`,
  `document_movements`) — сверка объектов по индексу (`list_objects`,
  `object_overview`): живой запрос по неверному/выдуманному имени даёт
  пустой результат, из которого легко сделать ложный вывод («данных
  нет», когда на самом деле нет объекта с таким именем).

## 2. Маршрут изучения подсистемы

```
1. list_objects по корням слов предметной области («импорт»,
   «таможенн») — карта подсистемы за пару вызовов; в выдаче приходят
   и константы/функциональные опции = готовый ответ «где включается»
2. object_overview / who_touches центрального объекта
   (кто_touches по регистру — все регистраторы и читатели одним
   вызовом; измерения в overview дают семантику связок)
3. help_status → help_search на ЛЕКСИКЕ из полученной карты
   (FTS не знает форм слова: ищи по корням с префиксом «*»)
   → help_read точных страниц; mentions в ответе — мост «дока ↔ код»
4. source_grep по телам — только для того, чего нет ни в индексе
   (имена — всегда, тела — после полной сборки, но без regex), ни
   в документации
```

Порядок «дешёвое → дорогое»: индексные вызовы — секунды и токены;
`source_grep` — полный обход исходников, ему есть место в конце.

## 3. Типовые сценарии

Короткие рецепты с фактическими вызовами — раздел «Рецепты» в
[TOOLS.md](TOOLS.md): исследование подсистемы, gap-анализ расширения
(`check_claims` батчем), поиск паттерна в телах, изучение объекта,
сверка «как должно работать» (дока) ↔ «как сделано» (код).

## 4. Карта честных границ

| Ситуация | Что это значит | Что делать |
|---|---|---|
| `holds: false` (field_not_found) | Доказанное «нет» — атрибуты объекта проиндексированы, поля среди них нет | Верный отрицательный вывод; посмотри `nearest` |
| `holds: null` (not_indexed) | «Нет» недоказуемо — объект индексирован частично | Не заключай «поля нет»; `predefined_details` / живая база |
| `_no_matches` | Честный пустой результат поиска | Переформулируй (корни, формы слов), не ретраи |
| `bodies_indexed: false` | Тела методов не залиты в FTS (сборка без пост-шага или слой отключён) | По телам — `source_grep`, по смыслу — `codesearch` |
| «векторный индекс пуст» (codesearch) | Векторизация не запущена | `start_semantic_index` / панель; запрос не ретраить |
| «Qdrant не ответил» | Сбой сервера — НЕ «индекс пуст» | Проверить сервис, повторить позже |
| предопределённых нет (`[]`) | У объекта нет Predefined.xml (наполняется данными) | Корректный факт, не сбой |

## 5. Анти-паттерны

- **Не ретраить честные отказы**: `_no_matches`, «векторный индекс
  пуст», отказы сборки повторяются тем же запросом только если изменил
  контур (собрал индекс, включил рантайм). Отказ — информация о
  состоянии, а не «попробуй ещё раз».
- **Не выдумывать имена объектов** (урок кейса «Продажи»): имя из
  задания/расширения может не совпадать с метаданными («ЮрАдрес…» vs
  «ЮридическийАдрес…» ловилось оракулом). Сначала `list_objects` /
  `search_function`, потом вызовы с именем.
- **Не читать дамп руками, пока есть тула**: ручной grep по выгрузке —
  это `source_grep`; чтение XML — `object_overview` /
  `predefined_details`; разбор форм — `find_in_forms`. Уход в ручной
  разбор — сигнал, что нужный тул не найден, а не что его нет.
- Не смешивать конфигурации: проверь `config` в вердиктах оракулов и
  `version` в `config_list` — правдоподобный `true` не от той базы
  хуже отсутствия проверки.
