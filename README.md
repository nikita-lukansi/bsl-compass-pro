[![Docker image: GHCR](https://img.shields.io/badge/docker%20image-ghcr.io%2Fnikita--lukansi%2Fbsl--compass--pro-2496ED.svg)](https://github.com/nikita-lukansi/bsl-compass-pro/pkgs/container/bsl-compass-pro)

**MCP-сервер для ИИ-агентов по 1С 8.3**: разведка конфигурации без
конфигуратора, поиск по коду семантикой и графом вызовов, живые данные
рабочей базы — только чтение, с обезличиванием.

**Статус: ранняя версия (0.1.0).** Проект только запустился и активно развивается: интерфейсы могут меняться, встречаются шероховатости. Смотрите issues, заводите свои — обратная связь решает, что чинить первым.

## Что это

Ты работаешь с 1С через агента-помощника. Компас даёт ему индекс твоей
конфигурации, и агент отвечает на вопросы про реквизиты, методы и вызовы
с доказательствами, а не «наверное». Масштаб — промышленный: выгрузка
КА 2.5 (653 756 методов) индексируется целиком, тёплый семантический
поиск — 0,05 с.

Всё живёт локально, в Docker на твоей машине. Наружу уходят только
проверка обновлений (выключается `UPDATE_CHECK=off`) и — если включена
семантика — тексты карточек методов (имя и сигнатура, не тела) в
эмбеддинг-API; его можно поднять локально. Подробности —
[SECURITY.md](SECURITY.md).

## Установка

Нужен **Docker Desktop** — весь контур живёт в контейнере. Образ
публикуется в GHCR, собирать ничего не надо:

```bash
curl -O https://raw.githubusercontent.com/nikita-lukansi/bsl-compass-pro/main/docker-compose.yml
docker compose up -d    # панель: http://127.0.0.1:8240/ui · MCP: /mcp
```

`.env` не обязателен — пустой контур стартует в bootstrap-визарде
панели. Настраиваешь сразу (хабы дампов, эмбеддинги) — положи `.env`
рядом **до** первого запуска, за образец — `.env.example`
(`curl -O https://raw.githubusercontent.com/nikita-lukansi/bsl-compass-pro/main/.env.example`).
Обновление: `docker compose pull && docker compose up -d`.

### Подключить агента

```json
{ "mcpServers": { "compass": { "url": "http://127.0.0.1:8240/mcp" } } }
```

Claude Code: `claude mcp add --transport http compass http://127.0.0.1:8240/mcp`.
Готовые снипеты с фактическим адресом — в панели: «Настройки →
Подключить агента».

### Из исходников

```bash
cp .env.example .env    # можно и позже — старт поднимется и так
docker compose build && docker compose up -d
```

## Быстрый старт

1. Выгрузи конфигурацию в файлы: конфигуратор → «Конфигурация →
   Выгрузить конфигурацию в файлы…».
2. Положи выгрузку в `./dumps/<Имя>/` — в корне подкаталога должен
   лежать `Configuration.xml`.
3. Открой панель → вкладка «Конфигурации» → «Добавить».
4. Укажи алиас и режим: «Быстрый» — только индекс, «Полный» — плюс
   векторы; галка «Собрать индекс» запустит сборку сразу.
5. Дождись карточки сборки на «Обзоре» — после неё тулы отвечают
   по этой конфигурации.

⚠️ Полная пересборка крупной конфигурации (>400k методов) — только при
остановленном qdrant (`docker stop bsl-compass-pro-qdrant` → сборка →
`docker start bsl-compass-pro-qdrant`): воркер съедает ~3,5 ГиБ, вдвоём
они не влезают в лимит Docker Desktop.

## Что умеет

- **Разведка метаданных** — `verify_field`, `object_overview`,
  `read_function`, `triggers_on_write`: ответы о коде и структуре
  с доказательствами, без открытия конфигуратора.
- **Граф вызовов** — `verify_call`, `call_paths`, `who_touches`,
  `repomap`: кто вызывает метод и куда приведёт изменение.
- **Семантический поиск** — `codesearch`: вектор + буквальный через
  RRF; на КА 2.5 тёплый запрос — 0,05 с.
- **Живые данные 1С** — `data_query`, `records`, `document_movements`,
  `event_log`: только чтение; офлайн-обмен через обработку
  «КомпасРантайм» маскирует строки per-chat токенами.
- **Панель** — реестр конфигураций, сборки, журнал вызовов, бэкапы,
  подключение агента.

Полный справочник тулов с примерами и честными границами —
[docs/TOOLS.md](docs/TOOLS.md).

## Три кейса

1. **«Где меняется этот реквизит?»** Разработчик получил задачу, а
   конфигурация чужая и огромная. `who_touches` + `triggers_on_write`
   дают карту регистраторов и обработчиков записи за минуты, а не за
   вечер ручного поиска.
2. **«Есть ли вообще такое поле?»** Агент не верит памяти:
   `verify_field` / `check_claims` отвечают вердиктом с доказательством
   — `holds: true / false / null`. Честное «не подтверждено» — тоже
   ответ.
3. **«Протяни остатки из живой базы»** Аналитику нужны цифры, агент
   строит `data_query`; в офлайне строки уезжают токенами
   (`Контрагент_Т3`), деанонимизация — только на выдаче человеку
   в панели.

## Когда НЕ использовать

- **Нужна запись в базу 1С.** Тулы только читают: SQL-пакет офлайна
  исполняет read-only SELECT (мутирующие ключевые слова — блок-лист).
- **Полный air-gap с семантикой.** Без сети индекс и структурные тулы
  работают, но эмбеддинг-API внешний — поднимай локальный vLLM/Ollama
  или оставайся в «Быстром» режиме без векторов.
- **Линт кода или настройка правил 1С.** Компас про поиск и
  доказательства, не про валидацию.
- **Нет XML-выгрузки.** Компас работает по выгрузке конфигурации в
  файлы — другого входа нет.

## Как работает

- **Индекс.** Выгрузка конфигурации разбирается Rust-строителем
  [gyrfalcon](https://github.com/aleksandrgradoboev-svg/gyrfalcon)
  (tree-sitter-грамматика BSL) в SQLite: методы, атрибуты, граф
  вызовов. КА 2.5 — 653 756 методов и 4.95M рёбер; полная пересборка —
  23 мин (пик 3,5 ГиБ), УТ 11 — 11 мин (1,28 ГиБ).
- **Семантика (опционально).** Карточки методов → эмбеддинги → Qdrant
  (int8-квантизация: 1,65 ГиБ RAM на КА); поиск — гибрид вектора и
  полнотекста.
- **Рантайм 1С.** Обработка «КомпасРантайм» в рабочей базе: онлайн
  (HTTP-сервис) или офлайн (файловый обмен через форму «Обмен»,
  read-only).
- **Панель.** Vue 3: обзор, сборки, журнал, бэкапы, настройки.

Маршруты изучения незнакомой конфигурации —
[docs/EXPLORATION.md](docs/EXPLORATION.md).

## Безопасность

Локальный запуск: порт прибит к `127.0.0.1`, мутации — за
`ADMIN_TOKEN`, живые данные — read-only, в офлайне — с обезличиванием.
Что уходит наружу и как сообщить об уязвимости — [SECURITY.md](SECURITY.md).
